# Evaluation

`python3 -m pytest -q` runs deterministic tests without phone/provider credentials. When `VOCALIS_TEST_DATABASE_URL` is configured, it also applies and reverses Alembic migrations against PostgreSQL and checks database-level tenant foreign keys, concurrent overlapping booking, persisted CRM/webhook state, SQLite transfer row fidelity, WAL-aware backup creation, and non-empty-target refusal. `python3 -m vocalis.evaluate` runs seven fixture scenarios and prints their checks and measured local server-turn times. These are fixture checks, not live-provider quality scores. Current checks cover tenant isolation, booking idempotency, voice booking confirmation and slot conflict, cancellation and rebooking, CRM outbox retries and stale-worker fencing, API-key scoping, Twilio signature calculation, retrieval isolation, escalation, audio input bounds, and cancellation of in-flight turns. The suite does **not** constitute a measured task-completion score or full conversation evaluation.

Planned seeded scenarios: booking, cancellation, FAQ, unsupported answer, prompt injection, CRM/calendar failure, human escalation, ambiguous intent, hallucination trap, interruption, and caller changes mind. Each scenario should pin a fixture tenant and provider fake, then compare expected state changes and tool calls. Deterministic metrics should remain separate from any model judge and human review. Collect live traces and sample sizes before publishing latency percentiles, token cost, or hallucination rates.
